# Additional implementation peer review

This review covered publication, authorization, configuration, pagination, serialization and both client modes in an earlier release. All 38 tests passed with the three live checks enabled. The [final release review](final-release.md) records the corrections and live verification.

| Priority | Finding and evidence | Correction |
| --- | --- | --- |
| P2 | The metadata preflight could use stronger secondary roles. Column discovery and uniqueness checks could succeed with privileges unavailable to the named metadata role alone. | Disable secondary roles on the preparation connection before discovery. Test with a login that has an additional stronger role. |
| P2 | `publishing.py:234` only grants service USAGE to the current reader. Two local releases with different readers produced additive shares. The catalog did not record the old reader. Its service access can persist if it still has parent privileges. Data queries remain caller-authorized. | Track the project-managed reader and retire its service grant after the replacement is healthy. Preserve independently granted shares. |
| P2 | `publishing.py:180` emits unconditional revocations by old object name. Snowflake returned 2003/42S02 for a confirmed nonexistent DEV table. `manage.py:187` runs this step after publishing and before writing the receipt. An identical retry repeats the same failing retirement. | Reconcile exact managed grants with Snowflake. Distinguish an absent grant, a renamed object and insufficient permissions. |
| P2 | `app/snowapi/paging.py:156` fails on a day-time interval. An actual nine-second Snowflake interval arrived as a Python timedelta, which the page serializer could not encode. A numeric-key MAP arrived as JSON text in the tested account. A native numeric-key mapping also failed response-model validation in a local fixture. | Define a lossless representation or reject unsupported projected types during release preparation. Test actual connector return types. |
| P2 | `app/snowapi/api.py:56` enables FastAPI's default Swagger page. The hosted page returned HTTP 200 but referenced CDN assets that the gateway's content security policy blocked. Chrome rendered no Swagger UI when given the hosted response and policy. | Ship Swagger assets on the service origin, or document the working JSON contract as the supported interface. |
| P3 | `client.py:115` leaves Playwright page bodies in the request context until the browser closes. Long exports can retain all previously read pages. | Dispose the page and health-check responses after reading their contents. [Playwright response disposal](https://playwright.dev/python/docs/api/class-apiresponse#api-response-dispose) |

The readiness check accepts any running package at the expected hostname. A local previous-version fixture passed. No failed promotion was observed in DEV. An expected package-version check would strengthen release verification. The earlier hosted-view 403 and the outstanding two-user policy test remain documented separately.
